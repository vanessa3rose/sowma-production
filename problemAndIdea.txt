Summary of Problem and Solution Idea
====================================

What I've learned so far:
-------------------------
- The export PDF feature is intended to show the same data as the on-screen chart for a selected custom date range.
- The export flow involves several files: the frontend passes the selected date range to the backend, which fetches metrics data for the export.
- The backend API endpoint (/api/metrics, implemented in api/metrics.ts) is responsible for filtering metrics data by date range.
- The frontend (fetchSocialExportBundle.ts, fetchMetrics.ts) correctly passes the custom date range to the backend.

What the issue is:
------------------
- The backend filtering logic in api/metrics.ts uses an OR condition:
    - It includes records where metricDate is in the selected range, OR where metricDate is null and lastSynced is in the range.
- This can result in the export including data outside the selected custom range, especially if there are records with metricDate outside the range but lastSynced inside.
- As a result, the exported PDF does not match the UI chart for custom date ranges (extra or missing data, flat lines, etc.).

In what files:
--------------
- The main issue is in api/metrics.ts (the backend API handler for metrics).
- The frontend files (fetchSocialExportBundle.ts, fetchMetrics.ts) are passing the correct date range, so the bug is not there.

What needs to change:
---------------------
- The backend query logic in api/metrics.ts should be updated to:
    - Filter primarily by metricDate for the selected range.
    - Only use lastSynced as a fallback if metricDate is missing and lastSynced is a valid substitute for the metric's date.
- This will ensure that the exported PDF matches the UI chart for custom date ranges, providing the expected user experience.

No code changes are included in this summary—this is a diagnosis and solution outline only.


Why the chart looks flat and has an incorrect y-axis:
The backend query currently includes data points outside the selected custom date range, due to the OR condition in the filter.
As a result, the exported chart may contain only a few points within the selected range, while most points are outside, causing the chart to appear flat or compressed.
The y-axis is scaled based on all returned data points, so if out-of-range values are included, the axis may be much larger than needed, making the actual data for the selected range look insignificant or flat.
This is why the exported chart does not visually match the UI chart for the same custom range.
